관리 계층

Topology Graph

Graph는 장치와 Interface Link의 관측 결과를 보여줍니다. Group 관리 계층을 추가로 생성하는 화면이 아닙니다.

조회 범위

Site·Group 선택은 Dashboard, Topology, 성능, Event와 Trap에 공통 적용되는 조회 조건이며 RBAC 권한이 아닙니다.

Layer와 LLDP

Layer는 Graph 배치 관점입니다. LLDP 재탐색은 선택 Group 단위 비동기 Job으로 실행합니다.

성능과 데이터 품질

RX·TX, CPU, Memory와 오류율을 기간별로 확인하고 PARTIAL·STALE·MISSING을 장치 장애와 구분합니다.

이벤트·SNMP Trap 관리

상태별 의미

OPEN

새 이벤트가 발생한 상태입니다. 대상 장치와 영향 범위, 심각도와 발생 근거를 먼저 확인합니다.

ACKNOWLEDGED

Operator가 이벤트를 확인한 상태입니다. 장애와 알림은 아직 활성 상태일 수 있습니다.

IN_PROGRESS

담당자가 지정되어 원인을 분석하고 조치하는 상태입니다. 조치 내용과 관련 근거를 기록합니다.

RESOLVED

자동 또는 수동 복구 근거가 확인된 상태입니다. 최종 영향과 조치 결과를 검토합니다.

CLOSED

복구와 운영 검토가 끝난 상태입니다. 종료 후 다시 발생하면 신규 연관 이벤트를 생성합니다.

역할별 처리 범위

Viewer · 조회

이벤트 목록, 상세, 처리 상태와 통합 Event Timeline을 조회합니다.

Operator · 관제·승인

이벤트 확인, Engineer 배정, 정책 설정, 복구 근거 검증, 해결 승인과 종결을 담당합니다.

Engineer · 실제 조치

배정된 이벤트의 조치를 시작하고 작업 내용과 결과를 Timeline에 남긴 뒤 Operator 승인을 요청합니다.

Admin · RBAC

사용자와 전역 역할만 관리하며 이벤트 처리와 운영 정책 변경에는 관여하지 않습니다.

Trap 처리 원칙

수신과 해석

Trap Listener가 원본을 수신하고 MIB Profile로 OID와 VarBind를 해석합니다. 미해석 원본도 보존합니다.

Event 연결

모든 Trap이 Event가 되는 것은 아닙니다. Rule과 중복·Storm 정책을 통과한 항목만 Event와 연결합니다.

재해석과 재처리

MIB 재해석은 의미를 다시 붙이는 작업이고 Event 재처리는 별도 Preview 후 수행하는 작업입니다.

자동 복구와 재발 처리
OPEN 또는 ACKNOWLEDGED 상태에서도 정상 상태가 확인되면 RESOLVED로 전환될 수 있습니다. RESOLVED 상태에서 재발 기간 내 다시 발생하면 같은 이벤트를 OPEN으로 되돌리고, CLOSED 이후 재발은 이전 이벤트와 연결된 신규 이벤트로 생성합니다. Suppression과 알림 전달 결과는 Lifecycle과 별도로 관리합니다.

구성 및 장치 관리

세 Profile 준비부터 장치 CRUD, Site·Group·Zone 구성과 최종 적용까지 안내합니다.

MIB 프로필

수집할 OID, Metric과 Trap Mapping을 정의하고 Module 의존성과 충돌을 검증합니다.

임계치 프로필

Event 발생·복구 조건과 지원 장치 유형을 정의합니다. Group에는 하나의 임계치 Profile을 적용합니다.

복구할 수 없습니다. 장치 다중 삭제는 사전 검사 후 삭제 가능한 대상만 처리하고 결과를 Audit에 남깁니다.

역할·용어 설명

운영에 필요한 기본 용어를 먼저 제공하고 개발·진단용 고급 용어는 별도 구역으로 구분합니다.

역할과 조회 범위

RBAC · Role

RBAC는 역할 기반 접근 제어입니다. Viewer·Operator·Engineer·Admin 네 개 전역 Role을 사용합니다.

Site · Group 조회 범위

Site·Group 선택은 모니터링 데이터를 좁히는 조회 조건입니다. 사용자별 권한 Binding이 아닙니다.

업무 분리

Operator는 NMS 운영, Engineer는 배정 Event 조치, Admin은 사용자와 Role 관리를 담당합니다.

관리 구조·Topology

Site · Group · Zone

Site는 최상위 경계, Group은 장치·Profile 적용 단위, Zone은 Group 내부 장치 분류입니다.

Topology

Device와 Interface Link의 관측 관계를 Graph 또는 장치 목록으로 보여주는 모니터링 화면입니다.

Membership · Link

Membership는 장치의 Topology 포함 관계, Link는 장치·Interface 사이의 관측 또는 수동 연결입니다.

Device · Interface

Device는 NMS 관리 대상의 불변 식별 단위이고 Interface는 장치의 물리·논리 포트입니다.

SNMP·수집

Polling · Trap · Inform

Polling은 NMS의 주기 조회, Trap은 장치의 비동기 통지, Inform은 수신 확인 응답을 요구하는 통지입니다.

MIB · OID · Profile

OID는 관리 항목 주소, MIB는 OID의 이름과 구조 정의, MIB Profile은 Module과 Metric·Trap Mapping 구성입니다.

Raw Counter · Rate

Raw Counter는 장치가 반환한 누적값이고, Rate는 두 정상 Sample의 차이와 시간으로 계산한 초당 변화량입니다.

Rollup · 데이터 품질

Rollup은 장기 조회용 집계값이며, 품질 코드는 GOOD·PARTIAL·STALE·MISSING·INVALID로 신뢰 범위를 표시합니다.

이벤트·운영

Event · Severity · Lifecycle

Event는 관제가 필요한 상태 변화, Severity는 심각도, Lifecycle은 OPEN부터 CLOSED까지의 처리 상태입니다.

복구 근거 · Suppression · 재발

복구 근거는 정상 복귀를 입증하는 Metric·Trap이며, Suppression은 알림 전달 억제, 재발은 복구 후 동일 조건의 다시 발생입니다.

장치·수집·데이터 품질

장치 도달 상태, 수집 서비스 상태와 Sample 품질은 서로 다른 상태 축입니다.

Job · Audit Log

Job은 비동기 작업이고 Audit Log는 작업자·대상·변경·결과를 남기는 기록입니다.

고급 진단 용어

Snapshot · as_of · Cursor

Snapshot은 일관된 데이터 묶음, as_of는 기준 시각, Cursor는 다음 목록이나 실시간 위치를 잇는 값입니다.

Raw Counter · Rate · Rollup

누적 원본값, 시간당 변화율과 장기 조회용 집계값을 구분합니다.

Backpressure · Watermark

처리량보다 입력이 많을 때의 압력과 내구성 저장 진행 위치를 나타냅니다.

Idempotency Key

재시도나 중복 요청이 같은 작업을 두 번 생성하지 않도록 요청을 식별합니다.

장애 진단·FAQ

장치 장애와 수집 장애를 먼저 분리하고, SNMP Profile → 수집 서비스 → 데이터 품질 → MIB Mapping → Event 관계 순서로 확인합니다.

장치가 Offline 또는 UNKNOWN으로 표시됩니다.
  1. 장치 관리 IP의 Ping과 UDP 161 경로를 확인합니다.
  2. SNMP Profile과 장치 ACL의 NMS 주소 허용 여부를 확인합니다.
  3. System Health에서 SNMP Collection과 최근 Polling 실패 원인을 확인합니다.
데이터가 STALE 또는 PARTIAL입니다.
  1. Snapshot의 as_of와 수집 완전성을 확인합니다.
  2. SNMP Collection 지연, Timeout, Backpressure와 장치 응답 시간을 확인합니다.
  3. 장치 장애로 단정하지 말고 최근 정상 Sample과 품질 코드를 비교합니다.
SNMPv3 인증 또는 암호화 시험이 실패합니다.
  1. Username, Security Level, Auth·Privacy 알고리즘이 장치 설정과 일치하는지 확인합니다.
  2. 자동 발견된 Engine ID와 Time Window 진단 정보를 확인합니다.
  3. Secret은 화면에 노출하지 않고 SNMP Profile 연결 시험 결과로 검증합니다.
Trap이 수신되지 않거나 Event로 생성되지 않습니다.
  1. 장치 Trap 목적지와 UDP 162 경로를 확인합니다.
  2. Trap 수신 화면에서 원본 수신 여부와 중복·미해석 상태를 확인합니다.
  3. MIB Mapping과 Event Rule 활성 버전을 확인합니다.
LLDP Link 또는 Graph 장치가 누락됩니다.
  1. 양쪽 장치의 LLDP 활성화와 LLDP-MIB 조회 권한을 확인합니다.
  2. 장치가 현재 Site·Group 조회 범위와 선택한 Topology에 포함되었는지 확인합니다.
  3. 미확인 이웃, Interface 재식별과 Link 최신성을 검토합니다.
OID 또는 Trap 이름이 숫자로만 표시됩니다.
  1. 필요한 Vendor Module과 의존 Module이 MIB Profile에 포함되었는지 확인합니다.
  2. OID·Metric·Trap Mapping 검증 결과와 Group 적용 상태를 확인합니다.
  3. 미해석 Trap은 MIB Profile 수정 후 재해석할 수 있습니다.
복구 후에도 Event가 종료되지 않습니다.
  1. 복구 조건과 유지 시간, 연관 Metric·Trap의 최신성을 확인합니다.
  2. 알림 억제 상태와 반복 Event 관계를 확인합니다.
  3. Engineer 승인 요청 후라면 Operator가 System 복구 근거와 작업 기록을 검토해 승인·종결합니다.
Event에서 Engineer를 선택할 수 없습니다.
  1. 현재 사용자가 Operator 역할인지 확인합니다.
  2. Engineer 계정이 ACTIVE 상태인지 확인합니다.
  3. Engineer 부하와 현재 배정 상태를 확인한 뒤 다시 선택합니다.
작업 기록 또는 상태 변경 기능이 비활성화됩니다.
  1. Operator는 직접 처리 또는 배정·승인, Engineer는 자신에게 배정된 Event의 조치 기록만 수행할 수 있습니다.
  2. 현재 Lifecycle에서 허용된 다음 동작인지 확인합니다.
  3. 필수 작업 기록을 입력하고 최신 Event 버전을 다시 불러옵니다.
메뉴 또는 설정 버튼이 보이지 않습니다.
  1. 현재 역할이 Viewer, Operator, Engineer, Admin 중 무엇인지 확인합니다.
  2. Site·Group 조회 조건과 역할 권한을 혼동하지 않았는지 확인합니다.
  3. NMS 운영은 Operator, 배정 Event 조치는 Engineer, 사용자·Role 관리는 Admin이 담당합니다.
장치 또는 Profile 삭제 버튼이 비활성화됩니다.
  1. 장치의 Group·Topology·Link·Event·Job 의존성을 확인합니다.
  2. Profile이 장치나 Group에서 사용 중인지 확인합니다.
  3. 연관성을 먼저 해제한 뒤 삭제 사유와 확인 문구를 입력합니다.
Site·Group·Zone을 삭제할 수 없습니다.
  1. Site는 하위 Group, Group은 하위 Zone과 소속 장치가 없어야 합니다.
  2. Zone은 배치 장치를 다른 Zone으로 이동하거나 해제해야 합니다.
  3. 조건을 충족하면 회색 버튼이 빨간색 활성 버튼으로 바뀝니다.
